# NVK bring-up

The renderer is linked against the package generated by **HayatoG/switch-nvk**.

## Local layout

Clone/build switch-nvk separately and point this project at the packaged directory:

```sh
git clone https://github.com/HayatoG/switch-nvk.git
cd switch-nvk

./build-native-tools.sh
./build-std-sysroot.sh
./configure-mesa.sh
meson compile -C mb
./package-nvk.sh

cd ../re4-switch
make NVK_SWITCH=../switch-nvk/nvk-switch
```

The expected package layout is:

```
nvk-switch/
  include/vulkan/...
  lib/libvulkan.a
```

## Current smoke test

`gxvk::initialize()` creates a Vulkan 1.3 instance through the statically linked Mesa NVK stack. The next renderer step is physical-device/queue discovery followed by the Switch-specific VI/nwindow surface and swapchain.

## Why NVK is external

Mesa/NVK is a large independently licensed dependency. We build/package it separately rather than committing generated libraries to this repository.
